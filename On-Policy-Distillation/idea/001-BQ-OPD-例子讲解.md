# BQ-OPD 例子讲解：老师教“算什么”，学生保留“怎么写”的选择

对应：[Idea 001](001-BQ-OPD-蒸馏计算行为而非等价写法.md)。下面的概率都是为了讲清楚方法而手工设定的，不是实验数据。

## 1. 先把原来那句话翻译成人话

原来的表述：

> 在可验证的完整计算单元上，只将满足同一任务输出合约的等价实现分组，蒸馏每组的总概率，去掉组内“你应该像 teacher 一样写”的监督。

更容易理解的表述是：

> **学生有几种不同的写法，如果它们确实完成同一种计算，而且符合题目要求，就把它们当成一种答案。老师教学生提高这种答案的总概率；至于学生更喜欢其中哪一种写法，这个 loss 不要求它跟老师一致。**

比如学生已经会写正确的因式形式，老师更喜欢展开形式。我们希望学生少算错，但是否需要强迫它把因式形式改成展开形式，是另外一个问题。

## 2. 数学例子：长方形面积

题目：

> 长方形两条边分别为 $x+2$ 和 $x+3$，请输出表示面积的算术表达式。

以下四个答案：

| 编号 | 答案 | 它在计算什么？ | 分组 |
|---|---|---|---|
| A | `(x + 2) * (x + 3)` | 正确面积 | 第 1 组 |
| B | `x * x + 5 * x + 6` | 正确面积 | 第 1 组 |
| C | `x * x + 5 * x + 7` | 正确面积加 1 | 第 2 组 |
| D | `x * x + 5 * x + 5` | 正确面积减 1 | 第 3 组 |

A 和 B 放在同一组，因为：

$$
(x+2)(x+3)=x^2+5x+6.
$$

**这里比较的是完整表达式实现的计算，不是看某一个 token 是否一样。**A 的第一个字符是括号，B 的第一个字符是 `x`，它们仍然可以完成同一种计算。

C 和 D 分别属于不同的错误行为，所以各自放在不同组。

## 3. 为什么要把概率相加？

假设 student 和 teacher 对四个完整答案的概率如下：

| 答案 | student 概率 | teacher 概率 |
|---|---:|---:|
| A：正确因式形式 | 0.40 | 0.10 |
| B：正确展开形式 | 0.10 | 0.80 |
| C：面积加 1 | 0.25 | 0.05 |
| D：面积减 1 | 0.25 | 0.05 |
| 合计 | 1.00 | 1.00 |

从这些数可以看出两个差别：

1. **能力差别：**student 答对的概率是 50%，teacher 是 90%。
2. **实现偏好差别：**student 在正确答案里喜欢 A，teacher 喜欢 B。

第一种差别值得学习；第二种差别是否值得学习，需要看任务。

### 3.1 如果把每个完整文本当成不同答案来对齐

目标会要求 student 接近 teacher 的四个数：

$$
(0.40,0.10,0.25,0.25)
\longrightarrow
(0.10,0.80,0.05,0.05).
$$

这样不仅减少 C、D，还会让 student 从喜欢 A，变成喜欢 B。

这张表为了简化，展示的是**完整答案分布对齐**。常见 OPD 实际在 student 前缀上做 token 监督；两者不是同一个实现，但都可能迁移 teacher 对具体表达的偏好。不能直接把表中的四个答案当成四个 token。

### 3.2 如果先把等价答案归为一组

“答对”这个事件包括 A 和 B，二者是互斥的完整输出，所以它的概率就是两种输出概率之和：

$$
P_{\rm student}(\text{正确面积})=0.40+0.10=0.50,
$$

$$
P_{\rm teacher}(\text{正确面积})=0.10+0.80=0.90.
$$

我们只对齐下面三个数：

| 计算行为 | student 总概率 | teacher 总概率 |
|---|---:|---:|
| 正确面积：A 或 B | 0.50 | 0.90 |
| 面积加 1：C | 0.25 | 0.05 |
| 面积减 1：D | 0.25 | 0.05 |

目标变成：

$$
\boxed{(0.50,0.25,0.25)\longrightarrow(0.90,0.05,0.05).}
$$

**“蒸馏每组的总概率”就是让 student 的这三个数接近 teacher 的这三个数。**

## 4. 学完以后，student 需要变成什么样？

以下 student 分布已经满足组概率目标：

| 答案 | 原 student | 一种满足目标的新 student | teacher |
|---|---:|---:|---:|
| A：正确因式形式 | 0.40 | **0.72** | 0.10 |
| B：正确展开形式 | 0.10 | **0.18** | 0.80 |
| C：面积加 1 | 0.25 | 0.05 | 0.05 |
| D：面积减 1 | 0.25 | 0.05 | 0.05 |

此时：

$$
P(A)+P(B)=0.72+0.18=0.90.
$$

student 已经像 teacher 一样，有 90% 的概率完成正确计算。但它仍然更喜欢因式形式 A：

$$
\frac{P_{\rm old}(A)}{P_{\rm old}(B)}=4,
\qquad
\frac{P_{\rm new}(A)}{P_{\rm new}(B)}=4.
$$

**这就是我们希望保留的选择：学生把正确计算学得更可靠，但不必改成老师最喜欢的写法。**

需要说清楚：类 loss 允许这个分布，却不会强制得到它。比如 A、B 的新概率是 0.45、0.45，也满足同一个组目标。实际神经网络共享参数，组内偏好仍可能变化。

## 5. “去掉组内监督”具体是什么意思？

如果 student 的组概率已经是：

$$
(0.90,0.05,0.05),
$$

它就完成了这个 loss 的目标。

即使 student 的 A、B 概率是 $(0.72,0.18)$，teacher 是 $(0.10,0.80)$，这个类 loss 也不再要求 student 改动 A 和 B 的比例。

**去掉的就是“正确计算已经学会了，但还要继续把 A 改成 B”的这部分训练要求。**

对应的公式非常简单。记三组概率为 $P_c$ 和 $Q_c$：

$$
\boxed{\mathcal L_{\rm class}
=\sum_{c=1}^{3}P_c\log\frac{P_c}{Q_c}.}
$$

只要各组的 $P_c=Q_c$，这个 loss 就是 0；它不再检查组内具体写法的比例。

## 6. 代码例子：同一个函数可以有不同实现

题目明确要求：

> 写函数 `solve(x)`，返回长方形面积。输入 `x` 是整数。只输出函数，不要 markdown 或解释。

实现 A：

```python
def solve(x):
    return (x + 2) * (x + 3)
```

实现 B：

```python
def solve(x):
    return x * x + 5 * x + 6
```

在这个整数算术例子中，两种实现对所有整数输入返回相同的结果，且都符合题目要求，可以归为同一个行为类。

teacher 如果更喜欢 B，我们仍然可以只教 student：**增加生成 A 或 B 的总概率，减少生成错误函数的概率。**

但“把代码块里的函数提取出来之后算对了”，还不代表原始输出满足题目要求。假设模型实际输出：

````text
```python
def solve(x):
    return (x + 2) * (x + 3)
```

这个函数可以计算面积。
````

提取出来的函数确实正确，但题目要求“只输出函数，不要 markdown 或解释”，原始输出违反了这个要求。

这就是原文里“输出合约”的意思：**题目要求什么输入、返回值和输出格式，我们就按这个要求判断是否等价。**

如果实际评测允许提取 markdown 中的代码，这两个输出就可能被视为等价。分组必须跟随实际任务要求，不能自己随意增加格式限制。

## 7. “完整计算单元”是什么意思？

一个完整表达式：

```python
(x + 2) * (x + 3)
```

可以判断它算的是什么。完整函数也可以判断输入输出关系。

但下面只有半句话：

```text
(x + 2) *
```

它还没有形成确定的计算，不能拿来与一个完整展开式判断等价。

因此初版想法是在**表达式完成、函数完成这样的边界**进行分组。如何在长推理中找到合适的局部边界，还没有解决。

同样，两个推理过程即使最后答案一样，也不能直接归为同一组：其中一个可能包含错误步骤，或者会让 student 后续更容易出错。

## 8. teacher 的“组概率”怎么得到？

在当前小实验中，先准备几个候选完整答案。student 和 teacher 分别给每个候选评分；teacher 可以额外看到参考解法。

完整答案的 log probability 来自它每个 token 的 log probability 相加，包含一致的结束边界：

$$
\ell_T(a)=\sum_j\log q_T(a_j\mid h,z,a_{<j}).
$$

然后在同一个候选集合 $S$ 上归一化：

$$
q_{T,S}(a)=\frac{e^{\ell_T(a)}}{\sum_{b\in S}e^{\ell_T(b)}}.
$$

最后把同组答案的概率相加。teacher 不需要专门输出一句“正确面积的概率是 90%”。

**这是有限候选集合内的近似。**如果集合遗漏 student 常见的错误答案，得到的组概率会误导训练。实际第一轮实验就出现过这个问题，所以后续加入了 student 自己生成的答案。

## 9. 它和“只奖励答对”有什么区别？

如果 teacher 永远把全部概率放在正确组，那么它提供的信息很接近“提高正确答案集合的概率”。这与 verifier-only / 正确集合训练高度接近。

只有当 teacher 对多个局部计算行为提供有价值的软概率时，它才可能带来超出二值正确性监督的信息。这个价值目前还没有被我们的实验证明。

而且 teacher 可能给错误组很高的概率。把答案分组，并不能自动把 teacher 变成一个可靠老师。

## 10. 最后用一句话记住

> **老师教学生更可靠地完成正确计算；当几种写法在实际任务中确实等价时，这个 loss 不要求学生连实现偏好也一起模仿。**

这是待验证的研究想法。当前实验能观察到实现偏好迁移减少，但尚未证明它比普通蒸馏或 verifier-only 更有效。
