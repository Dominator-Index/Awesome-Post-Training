# ReDraft 的理解：修订错误 rollout，再做 SFT

依据：[本地 ICLR 2027 投稿版](paper.pdf)第 3.2–3.3 节、公式 3 和 9，以及 Limitations。本文回答训练流程与 OPD 的区别，不是完整精读。

## 1. 对这篇方法的判断

**你的理解基本正确：ReDraft 提前生成模型回答，参考专家答案修订错误回答，通过验证后构造监督数据，最终做 SFT。ReDraft 本身没有使用普通 OPD 的逐 token teacher 分布匹配目标。**

论文确实训练了 OPSD 作为实验基线，所以“完全没有做 OPD”需要限定为：**ReDraft 方法自身的更新目标不是 OPD；OPSD 出现在对比实验中。**

## 2. 实际流程

对每个题目或图文输入 $x$，作者拥有专家参考回答 $y^*$ 和判断最终回答是否正确的验证器。

1. 初始模型只看 $x$，生成自己的回答 $\hat y$。
2. 如果 $\hat y$ 已经正确，直接保留它。
3. 如果 $\hat y$ 错误，让模型同时看到输入、专家参考和原始回答，要求保留有效内容并修正错误，生成修订回答 $\tilde y$。
4. 验证 $\tilde y$；只保留通过验证的结果。
5. 将保留结果组成训练对 $(x,\tilde y)$，对模型做监督微调。

这里的提示包含专家参考信息和具体修订要求，比泛泛地说“再想一下”更强。论文另外研究 ReDraft*：当小模型无法有效自我修订时，使用更强的外部模型修改其原始回答。

**最终 SFT 输入只有 $x$。参考答案和原始错误回答用于构造训练目标，并不会作为最终学生输入一起训练。**

## 3. 错误 rollout 是“不可信”还是“可利用”？

可以更准确地说：**错误 rollout 不能未经修正就当作正确答案进行 SFT，但其中的有效内容仍然有利用价值。**

一个最终答错的回答，可能包含正确的前几步、合理的组织方式和模型熟悉的表达。ReDraft 希望修改错误部分、保留有效部分，而不是直接用专家独立写出的回答替换全部内容。

这种做法的动机是让正确目标尽量接近原模型的行为，从而兼顾学习新任务和保留旧能力。但“接近”是设计目标及经验分析支持的性质，不保证每次修订都是最小修改，也不保证验证器确认了所有中间推理。

对于 OPD，错误 rollout 仍可以作为**访问过的前缀集合**：在错误发生前的前缀上，teacher 可以降低错误下一步的概率；在错误后的前缀上，也可以提供恢复指导。因此，最终答错本身不意味着整条 rollout 都不能用于 OPD，关键在于该前缀上的监督是否可靠。

## 4. 为什么最终更新是 SFT？

对固定的、已经构造好的修订数据集 $\mathcal D_{\mathrm{revised}}$，训练目标可写为：

$$
L_{\mathrm{SFT}}(\theta)
=-\mathbb E_{(x,\tilde y)\sim\mathcal D_{\mathrm{revised}}}
\sum_t\log\pi_\theta(\tilde y_t\mid x,\tilde y_{<t}).
$$

模型学习修订后的目标 token；训练时前缀来自这条保留的修订文本。这就是监督微调。

论文公式 9 从数据收集过程写出期望损失：

$$
L_{\mathrm{ReDraft}}(\theta)
=\mathbb E_{\mathcal D}\left[
S(x)\,
\mathbb E_{\tilde y\sim\pi_{\mathrm{ReDraft}}(\cdot\mid x)}
[-\log\pi_\theta(\tilde y\mid x)]
\right].
$$

$S(x)$ 表示该题目产生可保留目标的概率。作者说明，这个因子反映筛选后的数据出现频率，不是对每个保留样本再施加的额外权重。这里把收集过程固定下来；不会通过修订生成过程反向传播来优化参数。

## 5. 它与 OPD 的具体区别

论文公式 3 的 OPSD 对比目标是：

$$
L_{\mathrm{OPSD}}
=\mathbb E_{\hat y\sim\pi_\theta(\cdot\mid x)}
\frac1{|\hat y|}\sum_t
\operatorname{KL}\left(
\pi_T(\cdot\mid x,y^*,\hat y_{<t})
\middle\|
\pi_\theta(\cdot\mid x,\hat y_{<t})
\right).
$$

Teacher 根据参考信息，在 student 的原始 rollout 前缀上给出下一 token 的分布；更新只通过 student 分支。不同 OPD 变体可能采用其他散度，这里对应本文的 FKL 基线表述。

| 比较项 | 本文的 OPSD 基线 | ReDraft |
|---|---|---|
| 初始回答来源 | Student 自己生成 | Student 自己生成 |
| 参考答案的用途 | 给 teacher 构造条件分布 | 帮助修订完整回答 |
| 监督信号 | 前缀上的 teacher 概率分布 | 验证通过的完整文本 |
| 更新时使用的前缀 | 原始 student rollout 前缀 | 保留的正确回答或修订回答前缀 |
| 是否构造显式修订答案 | 不要求 | 对错误回答构造 |
| 是否筛选修订结果 | 无此必要步骤 | 使用验证器筛选 |
| 最终训练目标 | Token 分布匹配 | 目标文本的负对数似然，即 SFT |

## 6. 是否真的提前构造数据？

**是，实验实现采用一次性离线构造。**论文 Limitations 明确说明：修订数据集由开始训练时的策略构造一次；随着训练参数变化，目标会逐渐变旧；在线修订可能恢复与当前策略的接近程度，但尚未测试。

因此，实验流程应理解为：

```text
初始模型 rollout
    → 参考专家回答修订错误
    → 验证和筛选
    → 固定训练数据集
    → SFT
```

初始 rollout 来自当时的模型，并不使后续所有 SFT 更新都成为严格 on-policy 更新。论文的概念性表述中存在随训练重新生成语料的描述，但实验是否在线刷新应以 Limitations 的明确说明为准：本研究没有测试在线修订。

## 7. 它真正增加了什么？

从算法流程看，**“生成 → 改错 → 筛选 → SFT”确实是核心。**论文强调的进一步设计是：

- 修订从学生自己的回答出发，尽量保留有效内容，降低对外部专家表达的直接模仿。
- 在初始正确率接近零时，借助参考答案将失败回答转成可用的正例，而不只筛选极少数原本正确的回答。
- 同时评估新任务学习和旧任务遗忘，检查这种目标构造能否改善两者之间的权衡。
- 当 student 缺乏修订能力时，测试外部专家修订版本。

作者认为，OPSD 的局部 KL 信号可能更多集中在风格和格式差异上，未提供足够明确的任务纠正；ReDraft 则把纠正直接写进完整训练目标。这是论文的动机与实验解释，不能扩大成“OPSD 无法学习任何新任务”。

## 8. 对我们思路的含义

你想到的“学生答错后给参考信息、让它改对、再用于 SFT”，与 ReDraft 的核心机制直接重合。若沿这个方向推进，需要把 ReDraft 作为明确相关工作。

可能进一步考察的是：随着 student 更新在线重新修订、只对关键错误步骤构造监督、比较修订 SFT 与可靠的 OPD 指导、保留有效自我纠错过程。但这些只是待研究问题；其中在线修订已被作者列为未来方向，不能直接视为已经具有新颖性。
