# 12｜最小验证：DR 可以纠偏，但预测错误时也会放大方差

## 1. 结论先说

**估计器的结合成立；实际收益取决于预测残差的梯度几何。初版在 code 上有收益，在 math 上没有收益，不能据此宣称普遍有效。**

实验代码：[独立目录](../experiments-DR)，位于 `/usr/data/STOPD-DR-Pilot`。`estimators.py` 分别定义 IPW、proxy-only、DR；`pilot.py` 负责公共数据与评估。只导入官方 STOPD 的 core 与 sampling 函数，未修改 `/usr/data/STOPD`；原始 `main` 链接保持原指向。

## 2. 实际跑了什么

- 模型：本地 Qwen2.5-1.5B-Instruct。student 只看问题；teacher 使用同一权重、但提示中附 verified reference solution，是 privileged-context OPSD 诊断。
- 30 条真实 student sampled rollouts：math 15 / code 15；20 条训练 proxy，10 条 holdout。math 为两步算术，code 为简单 Python 函数；不是标准 benchmark。
- 生成 temperature 1、top-p 1、top-k 0，最多 64 token。teacher 在学生实际前缀上评分。
- proxy：student hidden 的前 16 个归一化坐标、student sampled log probability、entropy、位置与任务类型，ridge 回归 teacher feedback。
- 查询以 response 为单位，概率 25%；每个领域及总集做 20,000 次 mask 模拟，方法共用 mask，并额外算精确设计方差。
- 使用 8 个 logit-bias 参数方向的**精确局部梯度**，并非全模型梯度。定义 $f_k(a)=\cos(0.017(k+1)a)$，若 logit perturbation 为 $z_a+\sum_k\eta_kf_k(a)$，则

$$
v_{t,k}=\left.\partial_{\eta_k}\log p_\eta(y_t\mid c_t)\right|_{\eta=0}
=f_k(y_t)-\sum_a p(a\mid c_t)f_k(a).
$$

真实 teacher reward 为 $r_t=\log q_t(y_t)-\log p_t(y_t)$。比较的是固定 batch、固定分母下的 $\sum r_tv_t/N$。分母取完整数据 token 数以隔离估计器，不是在验证 STOPD 在线 lagged normalizer。

## 3. 第一轮：reward predictor 不是天然好的 gradient predictor

原始结果保存在 `results-round1.json`。下表是 response-level 独立随机查询的精确方差；IPW / DR 的条件均值都等于完整目标，所以也等于设计 MSE。

| Holdout | IPW | DR | DR / IPW |
|---|---:|---:|---:|
| math | 0.00451337 | 0.00494143 | 1.095 |
| code | 0.00186412 | 0.00104831 | 0.562 |
| all | 0.00231137 | 0.00243317 | 1.053 |

code 降低约 44%；math 增加约 9%；合并后初版反而增加约 5%。proxy-only 没有随机查询方差，但合并方向偏差 norm 约 0.0354，不能因 MSE 暂时较小就说保持 OPD 目标。

## 4. 修正 idea：用梯度残差校准预测器的信任程度

单纯优化 token reward MSE 不一定降低 response-gradient residual。第二轮保留 14 条 response 拟合 predictor，用其余 6 条训练集 response 做 calibration；没有用 holdout 标签拟合系数。

设 $G_u=\sum_t r_tv_t$，$B_u=\sum_t b_tv_t$，学习一个领域内系数：

$$
\alpha_d=\operatorname{clip}_{[0,1]}
\frac{\sum_{u\in\mathcal C_d}G_u^\top B_u}
{\sum_{u\in\mathcal C_d}\|B_u\|^2}.
$$

这是最小化 calibration 上 $\sum\|G_u-\alpha B_u\|^2$ 的结果；它不是 teacher/student distribution 插值，而是控制项强度。DR 校正后，对任意冻结 $\alpha$ 仍保持查询期望：

$$
\boxed{\widehat G_u=\alpha_d B_u+\frac{Q_u}{e_u}(G_u-\alpha_d B_u).}
$$

math 学得 $\alpha\approx0.279$，code 学得 $\alpha=1$。同样的 fit-14 predictor，分别比较未校准与校准，避免将训练样本变化误当成 calibration 效果：

| Holdout | IPW | DR fit-14 | DR calibrated | calibrated / IPW |
|---|---:|---:|---:|---:|
| math | 0.00451337 | 0.00559377 | 0.00450714 | 0.999 |
| code | 0.00186412 | 0.000676064 | 0.000676064 | 0.363 |
| all | 0.00231137 | 0.00270426 | 0.00219183 | 0.948 |

math 校准后基本持平；code 校准版比 IPW 方差低约 64%；合并约低 5%。这些仍是同一小 holdout 的探索性第二轮分析：**后续必须冻结方法并用新数据确认，不能作为独立 replication。**

## 5. 真正减少 rollout 的序列版本

导入 STOPD 的 $L=64,K=8$ inclusion probability，枚举每条 response 的全部 8 种停止预算。

$$
\widehat G_{\rm seq}=U_0+\sum_j\frac{I_j}{p_j}(d_j+U_{j+1}-U_j),\quad U_J=0.
$$

$d_j$ 是 block 梯度，$U_j$ 是过去训练数据中同领域/位置的平均剩余梯度，遇到已观察 EOS 后设零。预测器非常弱，特意另测 $4U$ 的错误预测。

| Holdout | STOPD IPW variance | sequential DR variance | 比值 |
|---|---:|---:|---:|
| math | 0.00230546 | 0.00228484 | 0.991 |
| code | 3.64653e-07 | 8.53815e-06 | 23.414 |
| all | 0.00108725 | 0.00107832 | 0.992 |

完整枚举的最大均值误差小于 $2.3\times10^{-9}$（浮点精度）；即使坏 predictor，也保留停止期望。但 code 的方差增加约 23 倍，坏 predictor 更糟。**序列 DR 有数学可行性，却没有被这次实验验证为实用改进。**

同样的停止设计在 399 个 holdout token 中期望观察 269.875 个，约 67.6%；这是 STOPD 本身的设计节省，两方法相同，不是 DR 的新增加速。

## 6. 对研究 question 的修正

**新 question：低预算 OPD 中，怎样让 cheap predictor 学会预测更新方向，而不是只预测 teacher 的 token 分数？怎样判断何时应当退回 IPW？**

重要的量是 $\|(r-b)v\|^2$ 或 response-gradient residual，不能只看 $|r-b|^2$。calibration 提供一个最小可实现证据；后续可以用少量 LoRA 参数的梯度 sketch 学习 predictor，并在新的 prompt split 验证。其创新性需要与已有 learned control-variate / budgeted OPD 逐项检索，不能把 scalar shrinkage 本身当创新。

## 7. 这次没有证明的事情

没有在线更新 student，没有测训练终局正确率，没有完成标准 math/code benchmark，没有测真实 teacher-query wall time 节省。所有 teacher labels 提前计算用于离线 audit；25% 查询是模拟预算。8 个方向的收益不自动推广到全模型梯度，参考提示 teacher 也不代表更大 teacher。

第一轮存在失败，序列版本仍失败。当前支持继续做独立验证，尚不支持上大规模训练或宣称新 SOTA。

CUDA_VISIBLE_DEVICES=2 /usr/data/OPD-BQ-Pilot/venv/bin/python /usr/data/STOPD-DR-Pilot/pilot.py
